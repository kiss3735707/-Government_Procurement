## 3. 数据怎么落

新增表，用 `CREATE TABLE IF NOT EXISTS` 挂到现有 `sql/schema.sql`。不改已有表的列含义。

**`llm_settings`（一行）**

- `base_url`、`api_key`、`model`、`reasoning`（默认 off）。
- 界面回显密钥时只显示末四位。接口日志不打印密钥。

**`announcement_ai`（一条公告一行）**

- `announcement_id` 唯一。
- `payload` JSONB：字典第六章结构，含包件数组。
- `status`：`pending` / `done` / `failed`。
- `model`、`error`、`tagged_at`。
- 重跑时整行替换 `payload`，并按公告删掉旧包件再插入。

**`award_packages`（一行一个包件）**

- `announcement_id`、`item_index`、`item_name`、`supplier_name`、`deal_amount`、`industry`、`content_tags`（JSONB）。
- 金额、供应商以这里为准做汇总。公告级行业、采购内容、结果状态留在 `payload` 里用 JSON 查询。

AI 金额区间用字典 E06，与规则标签 `amount_band`（`<50万` 等）不是同一套，不互相覆盖。

## 4. 怎样不碰现网

| 现网行为 | 二期做法 |
|---|---|
| 17:00 `node src/index.js --no-save` 采三类 | 命令不改。补采走单独命令，只传中标栏目 |
| 失败详情次日由 `listRetryQueue` 重试 `pending`/`failed` | 补采失败写成 `backfill_failed`，不进这个队列 |
| 18:00 `digest.js run --send` 只发当天 | 补采和打标都不调用它 |
| 管理界面 `/sales`、`/announcements` | 只加新页面，不改销售保存和发信 |
| 采集任务最长 2 小时 | 补采、历史打标避开 17:00–19:00，可中断 |
| 失败邮件挂在采集/日报单元上 | 新任务不用这两个单元的 `OnFailure` |

每日打标用新的 timer，建议 20:00（Asia/Shanghai），排在采集和日报之后。它只选取「今天发布、类型为中标、还没有 `announcement_ai` 成功记录」的行。失败只记在 `announcement_ai.error`，第二天补打，不补发邮件。

## 5. 任务顺序与完成标准

一次只做一个。上一个用户确认后才开下一个。

### T1 历史中标补录

探活（2026-09-28，未入库）：

- 现有 `beginDate`/`endDate` 字符串被忽略。查 2024-01-01 时接口 `total=75645`，第一页全是 2026-09-28。因此不能靠现有 `node src/index.js --date 2024-01-01` 补历史，它会从今天往前翻，100 页内到不了 2024。
- 有效参数是 `publishDateBegin` / `publishDateEnd`（上海时区毫秒，结束时间用当日 23:59:59.999，不用次日 00:00）。`2024-01-01` 当天中标 **3 条**，日期纯净；`2024-01-02` 当天 `total=70`。元旦条数少不代表档案断档。
- 客户端仍须按 `publishDate` 过滤：把窗口放宽到跨日时，会混入相邻日期。

完成标准：

1. 补采命令 `node src/backfill.js --from YYYY-MM-DD --to YYYY-MM-DD` 使用上述毫秒参数，只采中标，可从中断日继续。结束日须早于今天；17:00–19:00 拒绝启动。`--no-db` 只拉列表。
2. 重复执行不产生重复公告（沿用 `article_id` 幂等）。
3. 跑的时候 17:00 采集、18:00 日报仍按当天数据工作。

### T2 模型配置

1. 登录后能保存网关、密钥、模型名。默认模型 `DeepSeek-V4-Flash-0731-w8a8`，思考关闭。
2. 「测试连接」对网关发一条短请求，成功或失败有明确提示。
3. 这一步不给公告打标。
4. 销售清单、公告页、日报行为与改前一致。

### T3 历史中标打标

1. 手动分批。每条把标题和正文交给模型，要求按字典枚举输出第六章 JSON。
2. 校验失败或调用失败记 `failed`，不写包件；下次只重试失败和未打的。
3. 抽查若干条：包件行数与 JSON 里 `result_items` 一致，供应商和金额可对上正文。
4. 不改 `announcements.tags`，不发信。

### T4 每日新增打标

1. 新 timer 20:00 只打当天新增中标。
2. 关掉这个 timer 时，采集和日报仍成功。
3. 模型不可用时，当天日报仍发出，失败留到次日重试。

### T5 智能体只读接口

1. 单独令牌，不复用管理界面登录态。
2. 可按类型、日期、区划查询意向、招标、中标。
3. 返回已有公告字段和规则标签。中标若已打标，带上 `payload` 和包件行；没打标则 AI 字段为空。
4. 接口只读：不写库，不触发采集和发信。
