## 3. 关键校准发现（M2 前必须确认）

### 3.1 ⚠️ 接口日期过滤不可靠（最重要的发现）
- 实测：传 `beginDate/endDate` 后，返回数据**混入相邻日期**的记录（查 8-14 会返回 8-15 的记录）；
- **结论：不能依赖接口过滤，必须客户端按 publishDate 精确过滤**（已实现，验证通过）；
- 副作用：全量采集需翻页直到本页最早日期 < 目标日，页数比"按天过滤"预期多。

### 3.2 区划名称双写法（已处理）
- "浦东新区" 与 "上海市浦东新区" 并存（中标结果里常见后者）；
- 归一化字典已实现：16 区 + 本级，双写法 + 简称（"浦东"）均归一到标准名；
- 未知区划 → null → 进"待分配池"。

### 3.3 中标金额两种形态（已处理）
- 汇总式：正文"成交总合同金额（元）：421595.00"；
- 明细式：表格"中标（成交金额）"列（如 1279200.00 元）；
- 已统一：`awardAmount` = 明细式优先，汇总式兜底，`awardAmountSource` 标记来源。

### 3.4 采购人字段缺失（已处理）
- 中标结果里 `purchaseName` 常为 null，`author`（发布机构）有值；
- 已用 author 兜底 + `purchaserSource` 标记来源；二期可从正文"采购人信息"节提取更准确的采购人。

### 3.5 表格无 thead（已处理）
- 政采云正文表格多数无 `<thead>`，首行即表头，解析器已处理"首行当表头"。

### 3.6 政采云正文括号混用（已处理）
- "成交总合同金额(元)" 半角 与 "预算金额（元）" 全角并存，正则已兼容。

- 目标：采集 2026-08-14 全天三类公告，评估真实日增量与耗时；
- 预期：意向 ~15-30 条/日、招标 ~10-25 条/日、中标 ~10-30 条/日（待实测）；

- 源站压力评估：单日任务总请求 < 500，符合礼貌策略。
