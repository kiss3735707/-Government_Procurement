## ADR-001 采集范围：仅上海市，含三类公告

- **决策**：数据源仅上海市政府采购网（www.zfcg.sh.gov.cn）；采集三类：采购意向公开（`ZcyAnnouncement10016`）、采购公告/招标（`ZcyAnnouncement2`）、中标（成交）结果公告（`ZcyAnnouncement4`）。
- **理由**：用户确认只做上海；招标/磋商纳入是用户明确要求。
- **日期**：2026-08-15

## ADR-002 数据库：PostgreSQL 16（开源，非国产库）

- **决策**：PostgreSQL 16，同机部署；表结构见《数据库设计说明书》。
- **理由**：用户确认无国产化硬性要求；PG 官方支持 x86_64；SQL 设计零改动。
- **迁移预案**：若未来强制国产化 → openGauss/人大金仓（PG 系，SQL 微调 1~2 天）。
- **日期**：2026-08-15

## ADR-003 部署环境：信创服务器（海光/兆芯 x86_64 + Ubuntu）

- **决策**：Ubuntu Server 22.04/24.04，x86_64，可访问外网；systemd 原生部署（不依赖 Docker）。
- **理由**：用户确认；x86_64 用官方 amd64 软件，无 ARM 适配问题；systemd 规避内网拉镜像问题。
- **日期**：2026-08-15

## ADR-004 日期过滤：客户端强制，不依赖接口参数

- **决策**：采集按目标日期过滤必须在客户端做——用 `publishDate` 精确判断，绝不信任接口 `beginDate/endDate`。
- **证据**：实测接口传日期参数仍返回相邻日期记录（查 8-14 混入 8-15）。
- **日期**：2026-08-15

## ADR-005 意向明细拆表（1 公告 : N 明细）

- **决策**：`announcements` 与 `intention_items` 分开；一份意向公告的正文表格逐条拆为明细行（项目名/需求/预算/预计月）。
- **理由**：一份意向含多条商机，拆表才能按"单个项目"匹配与分析。
- **日期**：2026-08-15

## ADR-006 标签双通道

- **决策**：自动标签存 `announcements.tags`（JSONB + GIN 索引）；人工标签存 `announcement_tags` 表（可审计操作人）。
- **理由**：自动标签加维度不加表；人工标签需审计；支持任意维度组合查询。
- **日期**：2026-08-15

## ADR-007 区划归一化字典

- **决策**：销售清单只维护标准区名（16 区 + 本级）；源站两种写法（"浦东新区"/"上海市浦东新区"）及简称统一经 `normalizeDistrict()` 归一到标准名；未知区划返回 null 进"待分配池"。
- **证据**：实测 450 条样本存在双写法，28 种去重名称对应 16 区+本级。
- **日期**：2026-08-15

## ADR-008 中标金额统一语义

- **决策**：`awardAmount` = 明细式表格金额（`中标（成交金额）`列）优先，正文"成交总合同金额"汇总兜底；`awardAmountSource` 标记来源（table/summary）。
- **理由**：两种形态并存（汇总式 2/5、明细式 3/5 抽样），统一语义避免分析口径混乱。
- **日期**：2026-08-15

## ADR-009 采购人兜底策略

- **决策**：`purchaser = purchaseName ?? author`，并记录 `purchaserSource`；二期可从正文"采购人信息"节提取更精确采购人。
- **证据**：中标结果里 `purchaseName` 常为 null，`author`（发布机构）有值。
- **日期**：2026-08-15

## ADR-010 礼貌采集策略

- **决策**：请求间隔 ≥600ms，重试 3 次指数退避（1s/2s/4s），只拉当日增量，UA 标注 Mozilla 兼容、带 Referer。
- **理由**：公开信息低频采集，不冲击源站；robots.txt 被 307 重定向，以自律策略为准。
- **日期**：2026-08-15

## ADR-011 现网库与 jsonb 入库

- **决策**：PostgreSQL 16.15 部署在 `10.12.64.101:5432`，业务库/用户 `zfcg`；本机经 VPN `192.169.0.5` 直连。连接串只放 `.env` 的 `DATABASE_URL`。jsonb 列统一 `JSON.stringify` 后 `$n::jsonb`，避免 node-pg 把对象序列化成非法 JSON。
- **理由**：5432 已对开发 VPN 开放；源站 `announcementLinkDtoList` 直接绑参数曾报 `22P02 invalid input syntax for type json`。
- **日期**：2026-09-18

## ADR-012 M3 查询接口形态：CLI JSON，不先做 HTTP

- **决策**：分析查询以 `node src/query.js` 输出 JSON 为接口；管理界面 HTTP 放到 M5。
- **理由**：一期先打通标签过滤与聚合视图；避免与 M5 Web 控制端重复做一套服务。
- **日期**：2026-09-18

## ~~ADR-013 日报发送规则~~（被 ADR-014 替代）

- **决策**：每个销售一封、只含其区域；该销售当日 0 条则不发。未匹配区划进「待分配」发给 `DIGEST_ADMIN_EMAIL`（默认 SMTP 账号）。SMTP `smtp.mxhichina.com:465` SSL。防重发用 `daily_digests (report_date, sales_email, region)`，`status=sent` 不再发。
- **理由**：设计方案 §8；一期清单仅嘉定区一人，样本日无嘉定数据属预期。
- **日期**：2026-09-18

## ADR-014 管理员收全市日报

- **决策**：销售仍按区域各收一封、当日 0 条不发。`DIGEST_ADMIN_EMAIL` 收「全市」一封（当日全部公告，`region=全市`）。管理员邮箱与某销售相同时不另发该销售区域信。SMTP 以 `.env` 为准（当前 `smtp.qiye.aliyun.com:465` SSL）。防重发键仍是 `(report_date, sales_email, region)`。
- **理由**：用户 2026-09-18 指定 `635690160@qq.com` 为管理员，需看到全市政采信息，而非仅待分配。
- **日期**：2026-09-18
