# 智能体只读接口（草案）

状态：2026-10-22 收口。已部署到服务器管理界面。令牌在本机 `登录信息.txt` 的「智能体令牌」，不进 git。
日期：2026-10-22

标签的用途是业务分析，分析由智能体来做。接口因此分成三件不同的事：先问汇总数，再找相关公告，最后只对少数公告看全文和模型 JSON。智能体不要把几万条正文拉回去自己加总。

三个接口都只读。不登录管理界面，不写数据库，不触发采集、打标或发信。

---

## 1. 约定

- 路径以 `/api/agent/` 开头。管理界面的登录 cookie 在这里无效。
- 鉴权：`Authorization: Bearer <令牌>`。令牌来自环境变量 `AGENT_TOKEN`，不进 git，也不复用 `ADMIN_PASS`。
- 只提供 `GET`。其他方法返回 `405`。
- 日期按 Asia/Shanghai 自然日，格式 `YYYY-MM-DD`。
- 金额单位是元。
- 中标的统计金额用包件表 `award_packages.deal_amount`，不用公告头上的 `award_amount`。一条公告有多个包件时，用头金额会少算或和包件对不上。
- 供应商名称没有归并。同一家公司写法不同，会分成多行。接口不替智能体合并名称。
- 不返回 `raw_json`、`content_html`、模型密钥、销售邮箱和日报。

令牌不对：HTTP `401`，`{ "error": "unauthorized" }`。

参数不对：HTTP `400`，`{ "error": "参数错误", "message": "..." }`。

## 2. 汇总

`GET /api/agent/stats`

智能体问「谁中标多、哪个行业、哪个区、哪个月」时走这里。服务端分组求和，只返回几十行。

| 参数 | 必填 | 说明 |
|---|---|---|
| `group` | 是 | `supplier` 供应商、`industry` 行业、`district` 区划、`purchaser` 采购人、`month` 月份 |
| `type` | 否 | `award` 中标、`intention` 意向、`bidding` 招标。默认 `award` |
| `from` / `to` | 否 | 发布日范围，含首尾 |
| `district` | 否 | 标准区名，如 `嘉定区`。不能传 `全市` |
| `industry` | 否 | 只对中标有效，对应包件上的行业 |
| `supplier` | 否 | 只对中标有效，包件供应商名称，精确匹配 |
| `content_tag` | 否 | 只对中标有效，包件内容标签里包含这一项 |
| `limit` | 否 | 返回前多少名，默认 20，最大 100。按金额从高到低，金额相同再按笔数 |

中标按包件行汇总。意向和招标没有 AI 包件，只能按公告汇总，金额用 `budget_amount`，并且不能按 `industry`、`supplier`、`content_tag` 分组或过滤，传了返回 `400`。

```json
{
  "group": "supplier",
  "type": "award",
  "from": "2024-01-01",
  "to": "2024-12-31",
  "amount_basis": "package",
  "tagged_package_count": 18000,
  "untagged_notice_count": 1200,
  "rows": [
    {
      "key": "上海三凯工程咨询有限公司",
      "package_count": 12,
      "notice_count": 10,
      "amount_sum": 8600000
    }
  ]
}
```

`untagged_notice_count` 告诉智能体：这个时间范围内还有多少中标没打上标签，汇总不是全量。没打上的不进 `rows`。

`group=month` 时 `key` 是 `YYYY-MM`。`group=district` 时 `key` 是区名。

## 3. 查找公告

`GET /api/agent/announcements`

汇总里看到某个供应商或行业之后，用这里列出对应公告。每条只带检索需要的字段，不带正文，也不带整份模型 JSON。

| 参数 | 必填 | 说明 |
|---|---|---|
| `type` | 否 | `intention`、`bidding`、`award`。不传则三类都返回 |
| `date` | 否 | 只看这一天。不能和 `from` / `to` 一起用 |
| `from` / `to` | 否 | 发布日范围，含首尾 |
| `district` | 否 | 标准区名 |
| `industry` | 否 | 中标包件行业。传了就只返回中标 |
| `supplier` | 否 | 中标包件供应商，精确匹配。传了就只返回中标 |
| `content_tag` | 否 | 中标包件内容标签包含这一项 |
| `limit` | 否 | 默认 20，最大 50 |
| `offset` | 否 | 默认 0 |

```json
{
  "total": 10,
  "limit": 20,
  "offset": 0,
  "items": [
    {
      "id": 1835,
      "type": "award",
      "title": "青浦区农村公路日常养护监理",
      "purchaser": "某单位",
      "district_name": "青浦区",
      "publish_time": "2024-01-01T10:00:00+08:00",
      "project_code": "SHXM-00-20231206-1153",
      "award_amount": 1280000,
      "budget_amount": null,
      "packages": [
        {
          "item_index": 1,
          "item_name": "监理",
          "supplier_name": "上海三凯工程咨询有限公司",
          "deal_amount": 1280000,
          "industry": "未明确",
          "content_tags": []
        }
      ]
    }
  ]
}
```

意向和招标的 `packages` 是空数组。中标还没打完时 `packages` 也是空数组，智能体要看原因就再调详情。

## 4. 查看一条

`GET /api/agent/announcements/{id}`

只有需要引用原文、核对金额或解释某一条时才调。`id` 不存在返回 `404`。

在列表字段之外增加：

| 字段 | 说明 |
|---|---|
| `content_text` | 正文纯文本。没有详情时为 `null` |
| `tags` | 采集时的规则标签，如 `district`、`amount_band` |
| `intention_items` | 仅采购意向有，含 `item_name`、`budget_amount`、`expect_month` |
| `ai` | 中标且打标成功时，含 `payload`（字典第六章整份 JSON）、`model`、`tagged_at`。否则为 `null` |

不返回 HTML。

---

## 5. 智能体怎么调用

1. 先调汇总，例如「2024 年青浦区，按供应商」。
2. 看 `untagged_notice_count`。未打标很多时，在结论里说明覆盖范围，不把汇总数说成全年全部中标。
3. 需要名单时，用同一个供应商或行业去调查找。
4. 需要解释某一条时，再按 `id` 看详情。

---

## 6. 明确不做

- 不在接口里做供应商名称归并。
- 不提供写接口，不重打、不补采、不发信。
- 不把模型密钥和打标失败原文返回给调用方。详情里打标未成功时 `ai` 为 `null`。
- 本接口已挂在服务器管理界面。调用时使用 `Authorization: Bearer`，令牌不写进本文。
