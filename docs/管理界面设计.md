# 管理界面（Web 控制端）详细设计

版本：v1.0
日期：2026-08-15
配套：《数据库设计说明书.md》表结构、《政府采购信息采集与销售提醒系统-设计方案.md》M5

## 1. 定位与角色

管理界面是**运营/管理员**使用的 Web 控制端。销售**不登录**系统（每天收邮件日报）。

| 角色 | 权限 | 说明 |
|---|---|---|
| 管理员（admin） | 全部页面 | 系统部署者；默认账号 |
| 运营（ops） | 销售管理、公告查询、打标签、导出 | 日常维护者 |

> 一期只做"账号密码"登录（B8 决策：内网使用）；二期可接 LDAP/统一登录。

## 2. 页面清单总览

| # | 页面 | 路由 | 一级菜单 | 用途 |
|---|---|---|---|---|
| P1 | 登录页 | `/login` | — | 账号密码登录 |
| P2 | 仪表盘 | `/` | 仪表盘 | 今日概览、待处理提醒 |
| P3 | 销售管理 | `/sales` | 销售管理 | 区域-销售清单增删改、CSV 导入导出 |
| P4 | 公告查询 | `/announcements` | 公告数据 | 多维筛选查询、详情查看、打标签、导出 |

**顶部导航**（登录后）：仪表盘 | 销售管理 | 公告数据 | 日报 | 运维 | 设置 | 右侧：当前用户 + 退出

## 3. 页面交互设计

### P1 登录页 `/login`

```
┌────────────────────────────┐
│       政府采购提醒系统        │
│    [用户名]                │
│    [密码]                  │
│    [  登 录  ]             │
│ 错误提示：账号或密码错误      │
└────────────────────────────┘
```

**交互**：
- 提交 → POST `/api/login` → 成功写 session cookie，跳转仪表盘；失败红字提示
- 无"注册"入口；账号由管理员在系统设置（P8）维护
- 会话超时（默认 8h）后自动跳登录页

**后端**：`admin_users` 表（username, password_hash, role, is_active）；密码 bcrypt 哈希。

### P2 仪表盘 `/`

**布局**：顶部 4 个统计卡片 + 下方两张表。

```
┌──────────┬──────────┬──────────┬──────────┐
│ 今日新增意向 │ 今日新增招标 │ 今日新增中标 │ 待分配区划 │
│    12     │    8     │    15    │    3    │
└──────────┴──────────┴──────────┴──────────┘

┌───────────────────────────┬───────────────────────────┐
│ 今日三类公告走势（近7日柱状图）  │ 待分配池（未匹配区划公告）    │
│                           │  标题/区划/时间  [分配]    │
└───────────────────────────┴───────────────────────────┘
```

**统计卡片**：查询 `announcements` 按 `publish_time` 今日 + `type` 分组计数；待分配 = 区划未匹配到任何销售清单的记录数。

**待分配池表**：列 = 标题 | 原始区划 | 发布时间 | 操作[分配]。点"分配"弹窗选择销售 → 写入该公告的 `sales_owner` 人工标签。

**交互**：点击卡片数字 → 跳转 P4 且预填对应筛选（如"今日 + 类型=intention"）。

### P3 销售管理 `/sales`

**布局**：顶部工具栏 + 数据表格 + 分页。

```
[ + 新增销售 ] [ 导入CSV ] [ 导出CSV ] [ 仅看启用 ✓ ]

┌────┬──────┬───────────────┬──────────┬──────┬─────┬─────────┬──────┐
│ ID │ 姓名 │ 邮箱           │ 负责区域  │ 备注 │ 启用 │ 更新时间 │ 操作 │
├────┼──────┼───────────────┼──────────┼──────┼─────┼─────────┼──────┤
│ 1  │ 张三 │ zhang@xx.com  │ 浦东新区 │     │ ✓   │ 08-15   │ 编辑删除 │
│ 2  │ 张三 │ zhang@xx.com  │ 徐汇区   │     │ ✓   │ 08-15   │ 编辑删除 │
│ 3  │ 李四 │ li@xx.com     │ 普陀区   │     │ ✓   │ 08-14   │ 编辑删除 │
└────┴──────┴───────────────┴──────────┴──────┴─────┴─────────┴──────┘
```

**新增/编辑弹窗**：
```
销售姓名*   [            ]
邮箱*       [            ]        （校验邮箱格式）
负责区域*   [下拉：16区+本级     ]  （或输入，自动匹配标准区名）
备注        [            ]
启用        [✓ 默认勾选]
[ 取消 ] [ 保存 ]
```

**交互规则**：
- **新增**：必填校验（姓名/邮箱/区域），邮箱格式校验，区域用标准区名下拉（来自归一化字典，杜绝手写错名）；保存后列表即时刷新
- **编辑**：同新增弹窗回填；改区域不影响历史公告（配置与数据分离）
- **删除**：二次确认弹窗"删除后该销售将不再收到该区域日报，确定？"（物理删除；若想留痕用停用）
- **停用/启用**：行内开关；停用的销售收不到日报，但历史记录保留
- **一人多区**：同一邮箱多行，分别对应不同区域
- **CSV 导入**：弹窗选文件 → 预览前 5 行 → 校验 → 导入结果报告（成功 N 条 / 失败 M 条 + 原因列表）
- **CSV 导出**：导出当前筛选/全量，列 = `sales_name,sales_email,region,region_code,note,is_active`
- **CSV 模板下载**：导入弹窗内提供"下载模板"链接

**后端**：`sales_regions` CRUD；导入走事务（逐行校验，非法行跳过并报告）。

### P4 公告查询 `/announcements`

**布局**：左侧筛选区 + 右侧结果列表（分页）。

```
┌──────────────┬──────────────────────────────────────────┐
│ 筛选条件       │ 结果列表（默认按发布时间倒序，50条/页）       │
│              │                                          │
│ 公告类型  [▾]  │ ┌────────────────────────────────────────┐│
│ 区划     [▾]  │ │ 08-15 上海理工大学…政府采购意向        [详情]││
│ 发布日期 起止  │ │   [意向公开][本级][预算 172.6万]        ││
│ 关键词   [  ]  │ ├────────────────────────────────────────┤│
│ 采购人   [  ]  │ │ 08-15 上海市精神卫生中心…公开招标公告   [详情]││
│ 金额区间 [▾]   │ │   [招标][本级][预算 250万][开标 09-04]  ││
│ 项目编号 [  ]  │ └────────────────────────────────────────┘│
│              │                                          │
│ [查询][重置]   │  [< 1 2 3 4 5 >]  共 1,234 条            │
│              │  [ 导出CSV ]                               │
└──────────────┴──────────────────────────────────────────┘
```

**筛选条件**（全部可选，组合 AND）：
| 条件 | 控件 | 说明 |
|---|---|---|
| 公告类型 | 下拉 | 意向公开 / 招标 / 中标 |
| 细分类 | 多选下拉 | 公开招标/竞争性磋商/中标（成交）… |
| 区划 | 下拉 | 标准区名（16 区+本级） |
| 发布日期 | 起止日期 | 按 publish_time |
| 关键词 | 输入框 | 标题/采购人/项目名 LIKE 匹配 |
| 采购人 | 输入框 | 精确/模糊 |
| 金额区间 | 下拉 | <50万/50-200万/200-1000万/>1000万 |
| 项目编号 | 输入框 | 精确匹配 |

**列表行**：标题（超链接可点）| 类型徽标 | 区划徽标 | 关键摘要（意向=预算+预计月；招标=预算+开标；中标=金额+供应商）| 发布时间 | [详情]

**详情抽屉**（右侧滑出，或独立页）：
```
┌───────────────────────────────┐
│ × 公告详情                     │
│ 标题：…                        │
│ ─────────────────────────────  │
│ 类型：公开招标公告 区划：本级    │
│ 采购人：…  发布机构：…  时间：…  │
│ 项目编号：…  项目名称：…        │
│ 预算：250万 最高限价：250万     │
│ 开标时间：…  资金性质：国库+自筹 │
│ ─────────────────────────────  │
│ [标签] 产品线：[下拉+添加]       │
│        客户阶段：[下拉]          │
│        优先级：[高/中/低]        │
│        自定义：[输入] [添加]     │
│ 已有人工标签：实验室设备 × 高 ×  │
│ ─────────────────────────────  │
│ 意向明细（若为意向公告）          │
│  1. 集成电路测试设备 172.6万 09月 │
│  2. …                           │
│ ─────────────────────────────  │
│ 正文（HTML 渲染/纯文本切换）      │
│ 附件：[招标文件.xlsx] [明细.pdf] │
│ 源站链接：[打开原公告 ↗]         │
└───────────────────────────────┘
```

**详情抽屉交互**：
- 打标签：选择/输入标签值 → 保存 → 写入 `announcement_tags` 表，显示"已有人工标签"chip 列表（可 × 移除）
- 意向明细：仅 type=intention 显示，展开列出 N 条（读 `intention_items`）
- 正文：HTML 渲染为主，提供"纯文本"切换（防脚本，正文为源站富文本，需转义）
- 附件：链接可下载（一期存链接，点击跳源站）
- 源站链接：`https://www.zfcg.sh.gov.cn/site/detail?articleId=<id>`（新标签页）

**导出 CSV**：按当前筛选导出，列与详情字段对齐（见 §5 导出格式）。导出条数上限提示（默认 1 万条，超出提示改用条件筛选）。

### P6 日报记录 `/digests`

**布局**：筛选（日期范围）+ 表格。

```
[ 日期起止 ] [ 查询 ]

┌──────────┬──────────┬───────┬────────┬───────┬───────┬─────────┬────────┐
│ 报表日期  │ 收件邮箱  │ 区域  │ 意向数 │ 招标数 │ 中标数 │ 状态    │ 操作   │
├──────────┼──────────┼───────┼────────┼───────┼───────┼─────────┼────────┤

│ 08-15    │ li@xx    │ 普陀  │ 1      │ 0     │ 2     │ failed  │ 重发   │
└──────────┴──────────┴───────┴────────┴───────┴───────┴─────────┴────────┘
```

**交互**：
- **查看**：弹窗显示该封日报的邮件正文渲染
- **重发**：仅 failed/pending 可点；点击后重新调用发送逻辑，成功更新状态为 sent；防止误重发已 sent 邮件（按钮禁用）

**后端**：`daily_digests` 表查询。

### P7 采集任务 `/runs`

**布局**：顶部操作 + 最近任务表。

```
[ 立即采集 ] [ 采集日期: [2026-08-15] ] [ 仅看失败 ✓ ]

┌──────────┬───────────┬────────┬──────┬───────┬─────────┬────────┬──────────┐
│ 运行日期  │ 栏目      │ 状态   │ 页数 │ 获取  │ 新增    │ 详情OK │ 耗时     │
├──────────┼───────────┼────────┼──────┼───────┼─────────┼────────┼──────────┤
│ 08-15    │ 意向公开   │ success│ 3    │ 150  │ 68     │ 68     │ 3m12s    │
│ 08-15    │ 招标      │ success│ 2    │ 100  │ 68     │ 68     │ 2m40s    │
│ 08-15    │ 中标      │ failed │ 1    │ 50   │ 30     │ 30     │ 1m05s    │
└──────────┴───────────┴────────┴──────┴───────┴─────────┴────────┴──────────┘
```

**交互**：
- **立即采集**：指定日期 → 触发采集任务（异步，前端轮询状态）；用于补采/手工校准
- **失败重跑**：failed 行提供[重跑]按钮（幂等，安全）
- 状态徽标：success 绿 / failed 红 / running 蓝(旋转)

**后端**：`collect_runs` 表 + 触发采集服务（与 cron 同入口，带锁防并发）。

## 4. 通用交互规范

| 规范 | 说明 |
|---|---|
| 反馈 | 所有写操作成功/失败 toast 提示；失败展示后端 error 信息 |
| 删除 | 一律二次确认弹窗（写明后果） |
| 加载 | 列表/详情加载中显示骨架屏或 spinner |
| 分页 | 默认 50 条/页，可选 50/100/200 |
| 空态 | 空列表显示"暂无数据"+ 引导文案（如"点击右上角新增"） |
| 权限 | admin 可见"设置"菜单；ops 隐藏；前端隐藏 + 后端接口校验双保险 |
| 错误页 | 404/500 统一页面，带返回按钮 |

## 6. 技术实现建议（M5 开发用）

| 层 | 建议 |
|---|---|
| 后端框架 | Node.js + Fastify（与采集服务同语言/同仓库），REST API |
| 认证 | session cookie + bcrypt；`admin_users` 表 |
| 前端 | 轻量：Vue 3 + Element Plus（中文组件、表格/表单齐全）；或服务端渲染 + 少量 JS（若想更简） |
| 构建 | Vite 打包静态资源，Fastify 托管 |
| API 前缀 | `/api/*`，`/api/login`、`/api/sales`、`/api/announcements`、`/api/tags`、`/api/digests`、`/api/runs`、`/api/settings` |
| 权限 | 中间件按角色放行；写操作记录操作人 |
| 部署 | systemd 常驻服务（web） + 两个 timer（采集/日报），同机同端口 8080 |
| 数据安全 | 前端不可直接查库，全部走 API；导出走服务端生成 |

## 7. 与现有模块的关系

```
采集服务（cron 17:00）──▶ PostgreSQL ◀── 管理界面（Web, 常驻）
日报服务（cron 18:00）──▶   │             │
        │                  │             │
        ▼                  ▼             ▼
     邮件发送            daily_digests   collect_runs
                       announcements    sales_regions
                       intention_items  announcement_tags
```

- 管理界面**只读公告数据**（写入由采集服务负责），可写配置/标签/触发任务；
- "立即采集""重跑"通过管理界面调用采集服务同一入口（加锁防并发）；
- 销售清单（P3）与日报服务共享 `sales_regions` 表——改完当日生效。

## 8. 开发优先级（M5 内部排序）

| 优先级 | 页面 | 理由 |
|---|---|---|
| P1 | 销售管理 | 日报的地基，用户最急需（先给 CSV 初版导入） |
| P2 | 公告查询+详情+打标签 | 数据价值核心 |
| P3 | 登录+仪表盘 | 访问控制与概览 |
| P4 | 日报记录 | 运营审计 |
| P5 | 采集任务+设置 | 运维辅助 |

> 可先做"销售管理 + 公告查询"两个页面跑通（配合 CSV 导入），其余迭代补上。
